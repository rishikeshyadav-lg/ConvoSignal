# Project domain language

## ConvoSignal

**Goal**:
A distinct outcome the user is trying to achieve within a conversation.
_Avoid_: Treating every message as a separate goal.

**Material requirement**:
A user-grounded condition whose absence would substantially change whether a
goal was achieved. Explicit campaign identity, date boundaries and requested key
metrics are essential unless the user makes them conditional or optional.

**Optional detail**:
A condition the user explicitly makes discretionary, such as a metric requested
only if available. An evaluator cannot demote a requirement merely because it is
difficult to fulfill.

**Task outcome**:
How much of the requested work was accomplished, independent of how the user
felt about it.
_Avoid_: Using task completion as a synonym for confirmed user satisfaction.

**Explicit feedback**:
A user's stated acceptance or rejection of a particular result.
_Avoid_: Treating silence as an explicit reaction.

**Productive use**:
Observable use of a particular delivered result to accomplish or advance work.
_Avoid_: Treating any follow-up question as evidence of useful results.

**Evidence basis**:
Whether a judgment rests on a directly expressed reaction or an interpretation
of other available evidence.
_Avoid_: Presenting an inferred judgment as confirmed user sentiment.

**Inferred satisfaction**:
A judgment that available evidence supports successful fulfillment of the user's
goal without a directly expressed reaction. It does not establish that the user
read the result or felt satisfied.
_Avoid_: Confirmed satisfaction, silent approval.

**Honest inability**:
A supported explanation that necessary information or capability is unavailable.
An unmet request caused by that limitation alone does not establish dissatisfaction.
_Avoid_: Automatically equating unavailable data with an agent mistake.

**Unconfirmed recovery**:
A substantiated correction after user rejection, without later acceptance or
meaningful use establishing that the rejected issue was resolved for the user.
_Avoid_: Treating a corrected answer alone as confirmed recovery.

**Unverified correctness**:
The available evidence does not establish whether the answer's factual claims
are correct. This differs from a demonstrated error and can coexist with explicit
user acceptance.
_Avoid_: Incorrect, disproven.

**Mixed goals**:
Independent goals in one conversation have different satisfaction judgments and
no applicable overall feedback or explicitly decisive priority settles the result.
_Avoid_: Averaging away a failed goal.

**Conflicting evidence**:
Applicable positive feedback or use coexists with a demonstrated essential
failure that has not been resolved. Both observations remain relevant.
_Avoid_: Letting praise erase a known material error.

**Accepted scope change**:
A clear user decision to replace, narrow or otherwise change the requested
outcome. The revised goal supersedes the old scope while its history remains.
_Avoid_: Treating frustration, silence or giving up as permission to drop work.

**Courtesy acknowledgment**:
A polite response, such as a bare "thanks," that does not clearly establish
acceptance of the delivered outcome.
_Avoid_: Automatically treating politeness as direct satisfaction evidence.

**Overall acceptance**:
Clear user acceptance whose stated scope covers multiple delivered goals. It
does not resolve a known essential contradiction merely by being positive.
_Avoid_: Extending feedback about one result to the whole conversation.
