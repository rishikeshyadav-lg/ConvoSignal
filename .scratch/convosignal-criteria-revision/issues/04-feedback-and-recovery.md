# 04: Preserve feedback, contradictions and scoped recovery

**What to build:** An evaluator user can see how actual feedback and subsequent
corrections affect the revised goal judgment without praise hiding known errors
or a partial repair being presented as confirmed recovery.

**Blocked by:** 02 — Recognize supported completion without feedback.

**Status:** ready-for-human

**Implementation:** Complete; verified and available for review. Independent human validation remains pending.

- [x] Applicable explicit acceptance without a known essential contradiction can
  yield direct Satisfied while correctness remains unverified.
- [x] Positive feedback or use conflicting with a demonstrated essential error
  yields Neutral with both observations preserved until scoped resolution.
- [x] Bare courtesy does not establish direct acceptance. Permission, a topic
  change or an unrelated follow-up does not establish productive use.
- [x] Productive use cites a specific delivered result and its requirement scope;
  unrelated fulfilled details need not be individually acknowledged.
- [x] Verified correction after explicit rejection remains Neutral until
  acceptance/use covers all previously rejected material issues. Use covering
  only one of several corrected rejected issues retains partial confirmation.
- [x] Rejected or incomplete repairs remain negative where supported. Correcting
  an inferred-only failure does not invent negative user feedback or require
  confirmation of a reaction that never occurred.
- [x] Persist chronological evidence, task outcome, response, correctness and
  recovery separately. Paired workflow/replay tests cover acceptance, courtesy,
  contradictory praise, full/partial repair and old-policy stability.
- [x] Existing package and schema/compatibility checks stay green.
